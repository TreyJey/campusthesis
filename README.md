# CampusThesis

Прототип платформы управления выпускными квалификационными работами (ВКР): каталог тем, заявки на темы, рабочая область ВКР с этапами, загрузка файлов, отзывы руководителя, уведомления и рейтинг руководителей.

Версия: **1.0.0**

## Ключевой сценарий

Каталог тем → выбор темы → подача заявки → одобрение руководителем → рабочая область ВКР с 7 этапами → загрузка файла этапа → отзыв руководителя → переход к следующему этапу.

## Технологии

| Часть | Что используется |
|---|---|
| Бэкенд | Python 3, FastAPI, Uvicorn |
| База данных | SQLite, ORM SQLAlchemy |
| Фронтенд | HTML, Bootstrap 5, JavaScript |
| Документация API | Swagger (OpenAPI), строится FastAPI автоматически |

## Запуск

```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python seed.py                      # создать/пересоздать базу и тестовые данные
uvicorn main:app --reload
```

- Сайт: http://127.0.0.1:8000
- Swagger: http://127.0.0.1:8000/docs

`python seed.py` пересоздаёт базу с нуля, все изменения при этом пропадают.

## Роли

- **Студент** — каталог тем с фильтрами, заявка на тему, рабочая область ВКР, загрузка файлов этапов, оценка руководителя.
- **Руководитель** — заявки на свои темы (одобрить / отклонить) с фильтрами, список студентов, проверка этапов с оценкой и комментарием.
- **Методист** — все ВКР с фильтрами, перенос дедлайнов, добавление тем и архивация.

У всех ролей есть профиль: настройки уведомлений, уведомления, история действий, смена пароля.

## Статусы

- Заявка: `pending` → `approved` / `rejected`
- Этап ВКР: `locked` → `open` → `submitted` → `approved` или `revision` → `submitted` → …
- ВКР: `in_progress` → `defended`

Каждая смена статуса записывается в журнал действий и создаёт уведомление.

## Допущения прототипа

- **Авторизация упрощена.** После входа фронтенд хранит пользователя в `localStorage` и передаёт его id в запросах. Сервер проверяет роль и права по этому id, но не проверляет, кто именно прислал запрос. В рабочей версии нужна авторизация по токену (JWT).
- **Пароли хешируются SHA-256.** В рабочей версии — bcrypt.
- **Уведомления только внутри сайта**, без почты и мессенджеров.
- **Напоминания о дедлайнах** создаются при запросе уведомлений студентом (а не планировщиком по расписанию).
- **SQLite без миграций.** Схема меняется пересозданием базы через `seed.py`.
- **Файлы хранятся на диске** в папке `uploads`, в базе — только путь и метаданные.
- Допустимые файлы: PDF, DOC, DOCX, ZIP, 7Z, RAR, до 20 МБ.

## Что можно доработать

Авторизация по JWT, PostgreSQL и миграции, почтовые уведомления, планировщик уведомлений.
